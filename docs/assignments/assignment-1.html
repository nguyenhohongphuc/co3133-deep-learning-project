Problem statement

Motivation. Online clothing retailers receive product photographs faster than staff can label them, and the category a garment is filed under drives search, recommendation and stock reporting. Fashion-MNIST is the controlled-scale stand-in for that task: it keeps the ten-way garment decision while removing the confounds of colour, background and resolution, so that differences between models can be attributed to the model rather than to the data.

Input. One grayscale image x ∈ R1×28×28, pixel intensities in [0, 255] before preprocessing. Output. One of K = 10 mutually exclusive classes (T-shirt/top, Trouser, Pullover, Dress, Coat, Sandal, Shirt, Sneaker, Bag, Ankle boot). Prediction unit. One image, one label — single-label multi-class classification, not multi-label.

Formulation. Each model is a function fθ: R1×28×28 → R10 producing raw logits z = fθ(x). Class probabilities are p(y = k | x) = softmax(z)k and training minimises the mean cross-entropy L(θ) = -(1/N) ∑i log p(yi | xi) over the training split. The softmax is never applied before the loss: nn.CrossEntropyLoss takes the logits directly and applies log-softmax internally, so applying softmax first would compute it twice and flatten the gradients. Prediction is ŷ = argmaxk zk.

Main difficulties. (i) Several classes are visually near-identical at 28×28 — Shirt, T-shirt/top, Pullover and Coat share outline and texture, and this one cluster dominates the error budget of every model. (ii) The images are grayscale and low-resolution, so colour and fine texture cues are unavailable. (iii) The architecture families receive genuinely different views of the same image — a flat 784-vector, a 2D grid, or a sequence of rows, columns or patches — which is exactly the inductive-bias question this assignment is built around.

Research question

Under one fixed data split, one seed and one shared training protocol, how much does the way an image is represented to a model — flattened pixels, a 2D grid, or a sequence of rows, columns or patches — change classification quality on Fashion-MNIST, and is the quality gained worth the parameters and the training and inference time it costs?

Learning objectives covered

  • Complete PyTorch pipeline: Dataset, DataLoader, preprocessing, optimization, evaluation.
  • Linear/softmax, MLP, CNN, LSTM, and Transformer on the same task, all trained from scratch.
  • Comparison with multiple quantitative metrics plus qualitative evidence, not accuracy alone.
  • Analysis of inductive bias and input representation (flattened pixels, spatial features, row/column/patch sequences).

Preprocessing

No cleaning or resizing is needed: Fashion-MNIST ships as fixed-size 28×28 grayscale images with no invalid annotations. The pipeline is ToTensor() (scaling to [0, 1]) followed by Normalize(mean=0.286209, std=0.353160), both statistics measured on the 54,000-image training split only. No augmentation, resizing or padding is applied, so every architecture sees identical inputs. Input tensors after preprocessing are [B, 1, 28, 28] float32 with [B] int64 labels; the sequence models reshape that tensor inside forward(), so the data pipeline is shared unchanged.

Methodology

Pipeline overview

Walkthrough. scripts/prepare_data.py downloads Fashion-MNIST once. src/data/split.py produces the stratified 54k/6k split and commits it as a JSON index file, so every model in the comparison trains on byte-identical data. src/data/transforms.py converts each image to a float tensor and normalizes it with the training-split statistics; src/data/loaders.py wraps the three splits in DataLoaders with seeded workers. src/train.py reads configs/a1.yaml, seeds every RNG, builds the model through a registry and hands everything to fit() in src/engine/trainer.py, which runs the train/validate loop, logs one row per epoch to history.csv and saves best.pt whenever validation macro-F1 improves. src/evaluate.py then loads the best checkpoint, runs the test split exactly once, times inference, and writes test_metrics.json and the figures required by handbook §12.1.

Mandatory models

All five families are self-implemented as nn.Module classes in src/models/ and trained from scratch; library building blocks are PyTorch layers (nn.Linear, nn.Conv2d, nn.LSTM, nn.TransformerEncoderLayer). No pretrained weights are used. Every model returns raw logits [B, 10].

Inductive bias in one line each. Linear and MLP assume nothing about which pixels are neighbours. The CNN assumes locality and translation equivariance: one 3×3 kernel is reused at every position and pooling makes small shifts irrelevant. The LSTM assumes an ordering: it reads the garment top to bottom (rows), left to right (columns) or patch by patch, and must carry everything it needs in one 128-d state. The Transformer assumes almost nothing: every patch can attend to every other, and position is only known through a learned embedding, so spatial structure has to be learned from the data.

Training behaviour

  • Linear underfits: training and validation loss flatten together near 0.39–0.40. Best validation macro-F1 0.8658 at index 11; stopped after 17 epochs.
  • MLP overfits mildly: training loss keeps falling to 0.18 while validation loss stalls near 0.29 from about index 8. Best 0.9063 at index 22 of 28.
  • CNN converges fastest: best 0.9268 at index 7, early-stopped after 13 epochs, with the smallest train/validation gap at the selected epoch (0.200 vs. 0.206).
  • LSTM rows fits the training set hardest: validation loss bottoms out at 0.267 and rises to 0.296 while training loss reaches 0.14. Best 0.9118 at index 21 of 27.
  • Transformer shows little overfitting (0.263 vs. 0.291 at the last epoch) but plateaus early: best 0.9013 at index 11, stopped after 17 epochs. It looks capacity-unconstrained but optimisation- or data-limited at this scale and with these shared hyperparameters.
  • The best-macro-F1 epoch is not always the lowest-validation-loss epoch, which is why the selection rule is stated explicitly.

Confusion matrices

All five matrices share one shape: a strong diagonal for Trouser, Bag and the footwear classes, and one dense off-diagonal block among T-shirt/top, Pullover, Coat and Shirt. Models differ in how dense that block is, not in where it is.

Qualitative results

Comparison and discussion

Which is better, and by how much. The CNN has the highest test accuracy (91.82 %) and macro-F1 (91.76 %), the fewest errors (818 of 10,000), the shortest training time (367 s) and the second-smallest parameter count (50,378). It is 2.38 macro-F1 points above the MLP with 4.7× fewer parameters, and 1.87 points above the best sequence model (LSTM rows). The linear model is 7.68 points below the CNN but is the smallest (7,850 parameters) and the fastest at inference (0.52 µs per image).

Where the differences appear. Not uniformly. On Trouser, Bag, Sandal, Sneaker and Ankle boot every model from the MLP up is within about two F1 points. The gaps open in the upper-body cluster: from MLP to CNN, Pullover F1 rises 80.76 → 87.70 and Coat 81.62 → 86.99. Shirt stays the hardest class for every model (58.94 linear, 75.54 CNN).

Why: representation and inductive bias. Linear and MLP see a flat 784-vector in which a pixel and its neighbour are unrelated; local cues such as a collar, a button placket or a sleeve edge must be learned separately at every position. The CNN reuses one 3×3 kernel everywhere and pools small shifts away, which matches exactly those local cues — and it does so with fewer parameters, because the weight sharing replaces 200k dense weights with 18.8k convolution weights. The row LSTM keeps local structure inside each 28-pixel row but has to compress the whole garment into one 128-d state, and its training loss falls far below its validation loss. The patch Transformer has the weakest spatial prior (only a learned position embedding over 16 coarse tokens) and the most parameters (540,170), and under the shared hyperparameters it does not recover that prior from 54,000 images: it ends below the MLP.

Accuracy–speed–parameter trade-off. Linear, MLP and CNN form the frontier in Figure 3: nothing beats them on both quality and cost. The sequence models are dominated — the CNN is both better and faster at inference than every LSTM variant and the Transformer (13.34 µs per image, 3.8× the CNN). If inference cost dominated, the MLP is an intermediate choice (2.36 µs, −2.38 points).

What cannot be concluded. These are single-seed results with shared, untuned hyperparameters and unmatched model capacities. A 1–2 point gap between the MLP, LSTM and Transformer could change with another seed or a learning-rate schedule; the Transformer in particular is likely under-tuned. The result is a ranking for this protocol, not a general ranking of architecture families.

All three variants see all 784 pixels; only the scan order changes. Rows are best: garments are mostly left–right symmetric, so one row is a meaningful "slice" (shoulder line, waist, hem). Limitations and conclusion

Data limits. Fashion-MNIST is 28×28, grayscale, one centred object per image, with no metadata. It is a controlled benchmark, not a sample of real catalogue photographs, so absolute accuracies say little about production performance.

Method limits. One shared hyperparameter setting (Adam, lr 1e-3, batch 128, no scheduler, no augmentation) rather than a per-model search; dropout and normalization differ between models and parameter budgets are not matched, so no model is shown at its own best.

Experimental limits. A single seed (42): no variance or significance estimate. Two LSTM variants (columns, patches) come from an uncommitted working tree. Inference time is batched, forward-only, on one GPU, and would re-order on a CPU or at batch size 1.

Answer to the research question. Representation matters more than size here. Giving the model the 2D grid with a locality prior (CNN) gave the best quality at the lowest training time and with fewer parameters than the MLP; reading the image as a sequence (LSTM, Transformer) did not beat the CNN on any axis under this protocol. Among sequence encodings, row order worked best.

Future work. Repeat with three or more seeds and matched parameter budgets; tune the Transformer and LSTM on validation only (learning-rate schedule, depth, patch size); test controlled augmentation for the upper-body classes; compare LSTM with GRU; save per-image logits for every run.
